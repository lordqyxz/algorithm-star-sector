# 算法星域 · 视觉与交互规范

## 方向

以宏大行星、克制的战略界面、清晰的科学仪器语言建立体验。参考 Endless Space 2 的尺度与秩序感，不复制其标志、界面或资产。用户进入的是可以操演算法的星域；每一处强视觉都应帮助其判断当前位置、下一项任务或正在发生的因果变化。

主视觉使用 `public/art/solar-frontier.jpg`：右侧巨大的阴影行星、浅青大气边缘、左侧微小铜色恒星。让艺术画面占据屏幕，界面以细线、坐标、短标签和局部暗色底板浮于其上。标题不超过两行，不做占半屏的营销首屏。

三个课程领域「数据结构」「算法设计」「进阶方法」是完整课程并集的导航层级，不是三个等宽入口卡片。五份大纲的内容应合并去重；来源和覆盖信息属于章节详情，不能成为五份重复的课程入口。具体章节、关卡数和可用状态从课程数据读取，设计稿不虚构数量或进度。

## 状态与职责

- PixiJS 拥有星域、课程领域/章节选择、关卡选择、解锁、预测、操演、回退和结算；确定性模拟与命令日志仍是规则权威。
- React 只承载站点 HUD、航行日志、星图弹层容器等站点外壳。不得为了实现下述布局，把课程浏览或算法状态转移到 React。
- 所有用户可见中文，包括下面的示例标签，均经 `src/game/locale.ts` 取词。设计文档中的示例不是另一个文案源。
- 游戏场景必须按可用宽度重新布局。宽屏与手机使用同一组状态，使用不同坐标；不得将 960×600 画布整体缩至 390 像素来假装适配。
- `docs/动画绘制方法论.md` 的预测、对象恒常性、可逆分步与公式证据原则继续适用；其中旧课件组件的实现示例不代表恢复已移除的课件系统。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| void | `#050D11` | 页面底色、深空遮罩 |
| surface | `#09191E` | 工作区和高密度文字底板 |
| surfaceRaised | `#10252B` | 悬停、当前步骤底色 |
| line | `#294146` | 1px 分割线、轨道弱线 |
| lineStrong | `#527176` | 当前边框、坐标轴 |
| text | `#E9EEE8` | 标题、数值、主文本 |
| secondary | `#A0B6B7` | 说明与次级标签 |
| faint | `#748C8E` | 非必要坐标和装饰注记 |
| focus | `#9BD8DA` | 当前节点、选中控件、键盘焦点 |
| action | `#C7996B` | 主行动、航行目标、里程碑 |
| verified | `#91BA93` | 已验证、不变量成立、完成路径 |
| attention | `#D8BE70` | 当前读取的值、等待预测 |
| danger | `#D98272` | 冲突、错误预测的证据、非法操作 |
| boundary | `#B2A3C7` | 分割线/边界关系的局部科学标记 |

背景禁止蓝紫霓虹渐变。青色不用于所有装饰，铜色不铺满整屏。算法的多色有固定语义：左组/当前结构用青，右组/局部工作用铜，已确认用绿，正在读出的数值用黄，边界用低饱和灰紫。灰紫仅出现在算法关系中，不成为界面主题。

每种语义同时使用文本、位置、线型或形状。当前元素带实线描边和游标；已确认带勾或锁定标记；排除对象保留编号并降低饱和度；分界线用虚线。错误不得仅变红，也不得让整张操作台闪红。

主行动按钮采用铜色实底、深色文字；次行动透明底、浅青描边。暗色按钮上的正文至少使用 secondary。faint 不承载操作说明。正文必须置于足够不透明的底板或深色遮罩上，不能直接叠在行星高光上。

## 字体、线条与层级

- 中文优先 `PingFang SC`、`Microsoft YaHei`、系统无衬线；拉丁字母可沿用 Inter。数字、索引和公式使用 `ui-monospace, SFMono-Regular, Menlo, monospace`。
- 桌面章节标题 30–34px/1.2，关卡标题 26–28px，分区标题 18px，正文 15–16px/1.65，元数据 12–13px。手机标题 25–28px、正文至少 14px、主要操作 15px。
- 中文正文不加宽字距；坐标、英文短代号和短眉题可使用 0.12em 字距。长段落一行约 24–36 个汉字。
- 用 1px 分割线组织内容，边角半径 2–4px。节点、轨道和行星自然允许圆形；站点导航、任务面板和按钮不做药丸形。
- 仅当前选中节点允许小范围 8–12px 光晕。面板不使用大面积投影。仪器边角可以有 6px 短刻线，不能给每个矩形加四个装饰角。
- 普通页面只出现一个主行动。鼠标悬停用边框、明度和 2px 游标位移，不用卡片整体上浮。

## 桌面总览：1440×900

页面顶层：站点 HUD 高 64px，游戏场景高 800px，版权页脚高约 36px。此处场景坐标从 HUD 下方的 `(0, 0)` 开始。宽屏游戏充分使用可用宽度；不能继续居中一个窄的 960px 固定盒子。

| 区域 | 场景内坐标/尺寸 | 视觉与内容 |
| --- | --- | --- |
| 主艺术 | `(0,0) 1440×800` | cover，保持右侧行星；左侧遮罩约 94% void，至 60% 宽处降到 25%，右侧约 10%；另加底部遮罩确保命令区可读 |
| 左侧章节栏 | `(32,32) 240×704` | 顶部短眉题、30px 标题；下方领域切换，再列当前领域章节；栏右一根弱分界线 |
| 中央航线区域 | `(304,92) 768×420` | 当前章节的关卡节点、连线和短标签；绘制在深空与行星的交界；一个节点明显被选中 |
| 舰长状态 | `(1120,32) 288×124` | 右对齐显示军衔、引擎和累计航程，细线分隔；不拆成三张统计卡 |
| 星域坐标 | `(1120,190) 288×70` | 简短章节/区域编号，可与选中节点关联，低视觉权重 |
| 任务指令区 | `(304,552) 768×190` | 左侧任务编号、标题、两行任务目标；右侧难度/已完成记录和一个「进入操演」主行动；顶部细线，局部 surface 遮罩 |
| 下一里程碑 | `(32,752) 1376×28` | 左侧下一里程碑与剩余航程，右侧键盘/交互提示；不要做整行高亮进度条 |

HUD：左侧 28px 几何星标 + 站名，右侧三个文字入口「星域」「航行日志」「关卡星图」。选中项以下划线或 2px 顶/底线显示。取消蓝色胶囊导航。HUD 为接近不透明的 void，细底边，避免背景星点穿过文字。

左侧章节栏的节奏：标题区 72px；领域选择为三行 36px 的紧凑目录，当前行前有铜色 3px 竖线；再空 24px；章节行为 48–56px，编号 24px 宽，主名和小型进度组成。当前领域与章节都必须明确。章节较多时仅目录内部滚动，底部出现淡出提示。切换领域时保留玩家所选章节并更新中央航线。

中央不是随机散点壁纸。按依赖关系形成左下到右上的不对称弧形航线，控制一个视图约 5–9 个有标签的节点；其余通过章节切换呈现。已完成线为低饱和绿，当前可走线为青，锁定线为灰色虚线。节点名不与连线重叠。节点附近显示任务号和中文名称；奖励、课程来源与详细说明只在选中任务区出现。

锁定节点仍可选择查看需求；详情清楚显示前置关卡，主行动变为前往前置任务。不要让锁定状态成为不可点击、不可获知信息的灰色死区。

## 手机总览：390px 宽

视口宽小于 760px 切换为真实纵向版。页面自然滚动；手机不把所有信息挤进一屏。站点 HUD 高 56px，左右边距 16px：左侧短站名，右侧三个紧凑图标入口，均有可读名称或辅助标签；点击目标至少 44×44px。

Pixi 使用实际 CSS 宽度作为逻辑宽度，典型场景高约 1040px，坐标如下；高度依章节内容可增加：

| 区域 | 坐标/尺寸 | 行为 |
| --- | --- | --- |
| 艺术与标题 | `(0,0) 390×244` | 单独裁切行星右侧，保留大气弧线；标题 `(20,24)`，最多两行 |
| 舰长简报 | `(20,100) 350×54` | 军衔、引擎两行，航程可右对齐；保持常驻于总览顶部 |
| 领域切换 | `(16,184) 358×44` | 三个相邻文本 tab，当前下划线；不使用三张卡片 |
| 章节目录 | `(16,260) 358×224` | 至多四行可见，当前章节突出；更多项通过纵向滚动或展开展示 |
| 当前章节航线 | `(16,516) 358×214` | 简化为三段折线路径，每段 1–3 个节点；节点 44px 点击范围，标签至少 13px |
| 选中任务 | `(16,754) 358×206` | 标题、两行目标、先修/进度；主行动横向全宽，高 48px |
| 里程碑 | `(16,984) 358×36` | 一行简报，必要时换两行 |

手机章节列表与航线不得同时横向滚动。超过 9 个任务时使用章节内分段页，清楚显示当前分段；不以无限缩小节点解决。滚动后主行动跟随任务详情，不固定遮挡底部内容。

## 可玩关卡：桌面 1440×800 场景

关卡压低艺术亮度：背景仍保留右上行星边缘，但操作台是高对比、稳定的科学画布。画面中心必须是可操作的真实数据，而不是任务介绍卡。

| 区域 | 坐标/尺寸 | 内容 |
| --- | --- | --- |
| 顶部关卡标题 | `(32,24) 1376×76` | 返回章节、任务编号、关卡标题；右侧当前变体和步数 |
| 左侧任务指令 | `(32,124) 220×548` | 一句目标、当前阶段、对象图例、简短操作提示；总正文不超过约 120 字 |
| 核心算法工作区 | `(280,124) 820×438` | 数组/树/图/递归层/候选集合；周边留 24px 内边距；可见值、编号、方向箭头与局部标签 |
| 右侧测量区 | `(1124,124) 284×438` | 当前操作、公式、由工作区读出的数值；下方不变量及证据；每个公式值能在图中定位 |
| 操作台 | `(280,588) 820×84` | 上一/撤销、下一步主行动、重开；可选播放；快捷键作为弱标签；预测出现时以同一区域的选项替代下一步 |
| 因果记录 | `(280,696) 1128×72` | 本次发生了什么、为什么；只显示最近一条关键事件和可展开历史 |

工作区面积至少占场景宽的 55%，总场景可用高度的 50%。数据元素的文字 18–24px，数组格子 48–64px，节点至少 44px。使用实际值做对象身份；交互中的旧位置保留空位或索引，移动路径给出明确的单向/双向箭头。

任务指令与测量区采用上下分隔的读数排版，不做层层嵌套卡片。右侧不变量用绿色细左线和「保持成立」短标签，条件未满足时显示明确条件与数值证据。公式不能用 11px 字堆满侧栏，超宽公式分行或放到工作区下沿。

## 可玩关卡：手机 390px 宽

使用纵向场景约 1000–1200px 高，实际高度由数据布局决定。阅读顺序是标题 → 目标 → 工作区 → 当前变化/不变量 → 操作 → 证据，不复用桌面三列。

- 标题区 `(16,20) 358×84`：返回、关卡名、步数；标题 25px。
- 目标区 `(16,116) 358×64`：两行明确任务，当前阶段可在右上角显示短标签。
- 工作区 `(16,204) 358×340` 起：数组按行重排，树减小层间装饰空白，图使用可控平移且初始全貌可读。最多 6 个数组对象一行；第 7 个换行，按索引保留顺序，不截断数据。
- 当前变化与不变量 `(16,568) 358×100`：每项一至两行，必须在控制按钮之前可见。
- 操作区 `(16,692) 358×112`：第一行宽主行动，第二行撤销/重开/可选播放；各 44–48px 高。预测题出现时扩展本区高度，选项垂直排列。
- 数值证据 `(16,832) 358×140` 起：公式及其来源读数；可增加高度，不能省略推理必需证据。

对象多时优先分层、分页或有明确边界的工作区内平移。只允许复杂图/树工作区横向平移，整个页面不横向滚动。点击对象时显示紧邻其下的详情，不依赖 hover。键盘快捷键在手机隐藏，但按钮不隐藏。

## 章节详情、星图弹层和日志

星图弹层的 React 层只负责遮罩、标题与关闭。课程导航视图与选择仍由 Pixi 管理，使用共享课程数据和游戏命令。不能出现一套 React 关卡导航与一套 Pixi 地图各自保存选中状态。桌面弹层宽不超过 1200px，手机全屏，关闭控件至少 44px。

章节详情保留一个段落说明、先修要求与关卡清单。课程来源以紧凑文字列出，不能加高校标志模拟背书。尚未完成内容必须明确标为待开放，不能伪装可玩。

航行日志采用档案页：上部 200–240px 艺术裁切和舰长档案，下面按时间排列航段记录。军衔/引擎/航程在同一行读数中，不做四个相同统计卡。算法图鉴按章节归组，先显示已经亲自完成的算法证据；知识条目可展开，但不得重新长成课件站点。

## 动作与反馈

| 事件 | 动作 | 时长 |
| --- | --- | --- |
| 初次进入星域 | 艺术静态出现，HUD 透明度建立，当前航线逐段显现 | 400–600ms，总计不超过 900ms |
| 选中节点 | 描边明度变化，定位短刻线收拢，详情同步更新 | 160–220ms |
| 切换章节 | 航线淡出并替换，当前标记沿新起点建立 | 180–260ms |
| 数值移动 | 同一个对象沿真实目标路径移动，箭头保持到步骤暂停 | 280–420ms |
| 预测揭示 | 标出证据对象、更新解释与正确条件 | 180–240ms |
| 通关 | 完成路径点亮，依次显示实际跨越的军衔/引擎里程碑 | 每行约 350ms |

禁止持续扫描线、旋转 HUD、每个节点呼吸、背景大幅视差和无关粒子飞散。背景默认静态。允许非常低幅的当前目标明度变化，但不得成为读取状态的唯一手段。

`prefers-reduced-motion` 下背景和装饰完全静止，布局切换直接完成，对象直接置于目标状态，同时保留箭头、前后值和解释。任何步骤在暂停或无动画时都必须完整可读。

## 交付检查

- 首屏能一眼看到巨大行星、当前章节、可继续的任务；不存在白色卡片墙、蓝紫霓虹或巨型口号。
- 1440×900 下核心操演无需滚动即可访问下一步、撤销、当前不变量和公式证据。
- 390px 下中文正文不因画布缩放小于 14px，页面无横向溢出；任务按钮至少 44px；实际对象和公式仍可读。
- 切换领域、章节和星图弹层不会产生两份课程选择状态；返回时保留确定性进度。
- 图形、读数、方向和对象值同步；没有只改变公式字幕而图形不变的步骤。
- 成功、锁定、错误和选择均有非颜色信号；reduced motion 保留全部信息。
- 所有示例文案已落入 locale，界面显示的进度、课程数、军衔和引擎都来自真实状态。

## 桌面公式与文字边界补充（用户后续要求）

当前交付以桌面为优先验收目标。关系式与实际读数使用本地 KaTeX 排版并附 MathML；纯文本步骤说明和数学表达分开。公式层由游戏场景创建、定位、更新和销毁，原理抽屉打开时隐藏测量层。面板高度依据真实排版结果预留，不把分式、分段函数当作固定一行文本。

所有步骤说明、计数与右栏正文以实际文本高度决定操作栏起点；工作区高度使用稳定基线，避免自动扩展时递归增长。矩阵需要给行标题独立宽度；连线说明、节点名称和数值均有独立空间。同一对象的多个投影视图保留独立容器。
