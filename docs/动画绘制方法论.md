# 算法教学动画绘制方法论

## 目标

动画的目标不是让算法“动起来”，而是帮助学习者建立一个可以迁移的心智模型：

> 学习者能说清楚发生了什么、为什么发生、哪个量保持不变、公式中的哪一项记录了它，并能把这套关系迁移到一个新例子。

因此，每个动画都必须服务于一个可观察的学习行为，而不是服务于视觉效果。

## 研究依据转成设计原则

### 1. 先预测，再播放

只观看属于最低程度的参与。算法可视化研究中的“Responding”策略要求学习者先对下一步或结果作出预测，再观察可视化；在课堂场景中，它比单纯观看更能促进主动参与和问题解决。我们不把动画做成自动播放的视频，而是把关键转折做成“先猜一步”。

每个复杂概念至少设置一个预测点：

- 问题必须指向下一次状态变化，而不是考记忆术语；
- 选项要能暴露常见误解；
- 揭示答案时同时给出“图上证据 + 数值证据 + 一句话原因”；
- 预测错了也能继续探索，不能把交互做成考试惩罚。

### 2. 每一拍只表达一个因果关系

工作记忆需要同时处理图形、文字和时间变化。一个步骤中同时移动很多无关对象，会让学习者无法判断因果。每个教学拍点使用下面的结构：

```text
当前状态 → 一个操作 → 新状态
             ├─ 哪个量变了
             ├─ 哪个量不变
             └─ 公式中的哪一项记录了这次变化
```

如果一个步骤同时包含“拆分、排序、比较、合并”，就拆成多个步骤；如果某个对象只是装饰，就删掉。

### 3. 保持对象身份，动画只表现真实变换

对象在状态之间移动、缩放或改变颜色时，学习者才能把前后状态联系起来。数字、点、区间、递归子问题都应有稳定身份；不要把旧对象淡出、再凭空生成一个看起来相关的新对象。

允许的运动：

- 数组元素移动到它实际被分到的子数组；
- 点保留坐标，新增中线、条带或候选连线；
- 柱子保留层编号，只改变高度并同步更新数值；
- 被比较、被选中、被淘汰的对象出现局部强调。

不推荐的运动：

- 与算法状态无关的弹跳、旋转、连续缩放；
- 所有元素同时飞入而没有明确来源和去向；
- 只让公式逐字出现，却没有对应的数字或几何变化。

### 4. 公式是图形的测量结果，不是字幕

公式必须从可见数据中“读出来”。每次公式更新都要能回答：

1. 公式中的数字来自图上的哪里？
2. 本次操作新增或消除了哪一项？
3. 如果改变输入，哪个数字会随之改变？

例如主方法不应只依次显示 `T(n)=aT(n/b)+f(n)` 和结论，而应固定 `a、b、n`，改变 `f(m)`，同步显示每层的

```text
Wᵢ = aⁱ f(n / bⁱ)
```

以及由真实数值计算得到的柱高、相邻层比例 `r` 和主导层。学习者先看到 `16 → 16 → 16`、`1 → 2 → 4 → 8 → 16` 或 `256 → 128 → ...`，再把它们压缩成 `r=1、2、0.5`。

### 5. 图形、标签和解释要空间/时间相邻

与对象对应的标签应放在对象附近，并在对象变化的同一时刻更新。不要让学习者在图、公式、说明文字三处来回寻找同一个量。颜色只表达稳定语义，同时提供文字、形状或位置作为第二种线索，避免“只靠颜色看懂”。

推荐固定语义：

- 蓝色：左半、递归产生的子问题或当前结构；
- 橙色：右半、局部工作量或待比较量；
- 绿色：已经验证的答案/不变量；
- 紫色：边界、分割线或需要特别检查的关系；
- 黄色：当前需要读出的数值。

### 6. 主动引导注意力，但不让背景消失

当前操作对象用描边、聚光、箭头、局部放大或短暂变亮来强调；其余上下文保留低对比度，以便学习者知道它仍然存在。强调应该回答“现在看哪里”，而不是制造新信息。

一次只突出一个关系：

- 归并排序：当前正在比较的两个队首；
- 最近点对：中线附近的候选与被排除的远处点；
- 主方法：相邻两层的柱高比，而不是同时强调所有柱子。

### 7. 分段、暂停、回放是教学结构

默认由学习者控制步骤；自动播放是辅助浏览，不是默认教学路径。每个步骤需要：

- 可见的步骤标题；
- 一次可逆的状态变化；
- 一个短暂停顿；
- “上一页 / 下一页 / 重播”；
- 最终静态状态，即使关闭动画也能读懂。

复杂内容使用“预训练 → 预测 → 展示 → 自我解释 → 迁移”五段式：

1. 先认识对象和符号；
2. 预测下一步；
3. 播放一个因果变化；
4. 用一句话解释为什么；
5. 改变输入或换一个位置，检验规则是否仍然成立。

### 8. 交互必须推动理解，而不是增加按钮

按学习目标选择交互层级：

| 层级 | 学习者做什么 | 适合用途 |
| --- | --- | --- |
| 控制观看 | 手动前进、回退、重播 | 让时间节奏可控 |
| 预测回答 | 猜下一步、猜主导层 | 暴露并修正直觉误解 |
| 改变参数 | 改变 `n`、`a`、`b` 或点的位置 | 观察不变量和边界 |
| 构造/解释 | 排列一步、选候选、写一句理由 | 检验迁移和深层理解 |

不要为了“更交互”而自动加入复杂编辑器。每个交互都必须对应一个可验证问题。

## 当前站点的绘制契约

以后新增 lesson 时，数据结构至少要能描述：

```ts
type LessonStep = {
  title: string
  question: string
  visualState: unknown
  formula: React.ReactNode
  invariant: string
  evidence: string
  conclusion: string
  prediction?: {
    prompt: string
    options: string[]
    answer: number
    explanation: string
  }
}
```

实现时遵守以下检查：

- `visualState` 是算法状态的可读投影，不是装饰参数；
- `formula` 中每个关键数字在图中有来源；
- `invariant` 明确说出本步没有改变的量；
- `evidence` 给出数字、距离、层工作量或候选数量；
- `prediction` 在关键转折前出现；
- Anime.js 只负责状态变化的过渡，不拥有算法状态；
- `prefers-reduced-motion` 下直接显示最终状态，不依赖运动才能理解。

## 针对课程动画的落地规则

### 归并排序

不要只画递归树方块。使用真实数组 `[8,3,7,4,1,6,2,5]`，让学习者看到：

1. 数组如何按位置分成两半；
2. 子数组如何继续分解到单元素；
3. 两个队首如何比较，较小者为什么先进入输出；
4. 每个合并层为什么总共处理 `n` 个元素；
5. `log₂ n` 来自树高，而不是凭空写在结论里。

### 最近点对

不要只显示最终的 `C–E=2`。逐步显示：左右局部最小值、`δ=min(δL,δR)`、中线两侧的 `δ` 条带、被条带排除的点、保留下来的跨界候选，以及最终距离比较。每条候选线都应能被解释为一次真实的距离比较。

### 主方法

不要把三种情况当作三个孤立例题。固定 `a=2,b=2,n=16`，只替换 `f(m)`，并让同一组层编号和计算台同步更新。学习者应先观察层工作量序列，再观察 `r=Wᵢ₊₁/Wᵢ`，最后得到“根部 / 每层 / 叶子”的分类。分类结论必须能被新参数反例检验。

### 堆排序

同时保留“完全二叉树”和“数组”两种视图：树解释父子堆序，数组解释原地交换和有序后缀。每轮明确标出根节点、被交换的末尾元素和重新堆化的路径；不要只显示最终升序数组。

### 快速排序

把主元、扫描中的当前元素、左/右分区和已确定的位置区分开。重点不是展示一次漂亮的交换，而是让学习者看到同一个递推式

```text
T(n) = T(k) + T(n-k-1) + O(n)
```

如何随着分区形状改变：`k≈n/2` 时递归树高度约为 `log n`，`k=0` 时退化为链。必须同时展示均衡和极端情况，避免把快速排序简单等同于稳定的 `Θ(n log n)`。

## 设计思路面板（沙盘推演的固定第三段）

每个沙盘推演（课件页）在结论之前固定渲染 `DesignNotes` 面板，用三段把"设计思路"变成可检验的内容：

1. **关键观察**：这个算法之所以成立，依赖的那一个事实（例如"合并两个有序数组只需线性扫描"）。
2. **换个设计会怎样**：一到两条替代设计与代价对比（例如"若改用快排：省辅助空间，但最坏 Θ(n²)"）——取舍必须是真实的工程取舍，不是修辞。
3. **带走这一招**：一道迁移题（复用预测题组件），检验学习者能否把设计思想用到新场景。

王国模式的操演关在通关后解锁同一结构的"设计思路"卡（数据来自关卡 JSON 的 `insight` 字段），保持游戏与推演的术语与结构一致。

## 验收与迭代

每个动画交付前用五个问题验收：

1. 关闭自动播放，学习者能否手动复现每次状态变化？
2. 随机暂停时，能否指出当前变化对应的公式项？
3. 能否说出一个不变量，而不只是复述标题？
4. 改变一个输入后，能否预测至少一个结果变化？
5. 关闭运动或使用键盘时，信息是否仍然完整？

最终评价不要只看“好不好看”或“是否完成播放”，至少记录：预测正确率、公式—图形对应率、迁移题正确率，以及学习者是否能用自己的话解释原因。
