# 前端游戏引擎选型调研（2026-09）与结论

> 结论一句话：瓶颈是"缺一层引擎式抽象"，不是"缺一个引擎"。不引入现成引擎；把内部
> trace/命令日志层升级为游戏框架（`src/game-framework/`），PixiJS 留作性能逃生通道。

## 二、三条路线的裁决

1. **整体采用引擎重写**：否——canvas 承载 UI 违反"语义控件/键盘可达/无 JS 可读"红线；双份状态真相；LLM 语料错位。
2. **只引入 PixiJS 渲染层**：不划算——单屏几十个实体够不着 WebGL 收益阈值，换来 −252KB 与无障碍归零。留作逃生通道。
3. **升级自有引擎为内部游戏框架（采用）**：React 状态即游戏状态；DOM/SVG 保留可达性与语料优势；补四层薄抽象。

## 三、采用的框架蓝图（src/game-framework/）

| 层 | 职责 | 实现 |
| --- | --- | --- |
| 舞台 / Sprite（精灵） | 拥有独立身份与坐标的图形元素；逻辑位置即数据，DOM 节点跨帧持久 | `stage.tsx`：绝对定位 actor + CSS transform 过渡 |
| 缓动插值（Tween） | 两个关键状态之间按缓动函数生成中间帧；reduced-motion 自动降级 | CSS transition 承担位移动画（anime.js 已有依赖，用于入场动画） |
| 输入（Input） | 键盘快捷键 + 指针；语义控件不退化 | `keys.ts`：useGameKeys 映射 |
| 音频（Audio） | 已按产品决策移除 | — |
| 镜头（Camera） | 世界地图扩大后的平移/缩放 | 预留接口，暂无消费者不实现（YAGNI） |

术语表：**Sprite（精灵）**＝画面中拥有独立身份与坐标、可被单独驱动移动的图形元素；**Tween（缓动插值动画）**＝在两个关键状态之间按缓动函数自动生成中间帧；**Stage（舞台）**＝精灵的容器与坐标系；**Actor（角色对象）**＝引擎中带身份的实体；**场景图（Scene Graph）**＝舞台元素的层级组织。

要点：Sprite 的身份（cell id）跨帧保持、坐标变化由缓动插值生成中间帧——这正是方法论"移动真实数字"的引擎化落地。

## 四、二次调研裁决（2026-09，约束更新后）

约束更新：无障碍出圈（不再构成任何否决理由）；对 PixiJS 的拒绝重新评估；Phaser 4 一并重审。二次调研硬数据：

| 指标 | PixiJS v8（8.20.1） | Phaser 4（4.2.1） |
| --- | --- | --- |
| 周下载 | 76 万（@pixi/react 6.4 万） | 26.3 万 |
| 包体 gzip | ~258KB | ~356KB |
| TS | 源码即 TS，类型一等公民 | JS 源码 + 独立类型文件 |
| v4/v8 语料 | v8 语料约 55-70%（官方文档 100% v8） | v4 语料 <5%（教程/示例几乎全 v3） |
| React 19 | @pixi/react 声明支持但有 StrictMode 崩溃与维护滞后（#602/#613/#630） | 官方 react-ts 模板（仍标 Phaser 3） |

**裁决：采用 PixiJS v8 作为游戏表现层，指令式懒挂载（不使用 @pixi/react 作为主驱动）。**

- 前提不变：模拟层/命令日志/奖章/存档全部留在 React 侧，引擎只做表现层渲染。该前提下 Phaser 的全家桶溢价（Scene/物理/音频/Tilemap）大多落空，而代价（+100KB、v4 语料真空、双状态源）是实打实的。
- 组合：pixi.js 8.20.x（表现层）+ pixi-viewport v6（镜头，后续）+ pixi-filters（特效）+ anime.js（缓动插值，已有依赖）。
- 懒加载：游戏内 `React.lazy(() => import('.../PixiShelf'))` 动态分包；学院/沙盘模式零成本。
- 迁移三步：① 指令式 Application 挂载/销毁封装；② React 模拟层快照单向驱动 Pixi 容器树（Sprite 身份跨帧保持，坐标缓动走 anime.js）；③ 按网格 → 角色 → 镜头 → 特效逐模块替换验收。
- Phaser 4 重新触发条件：要做带内置物理/音频/Tilemap 的完整游戏世界，且等到 2027 年 v4 语料成熟。
