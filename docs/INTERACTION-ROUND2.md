# 第二轮：可探索、可回退的算法实验台

日期：2026-10-25。本文记录第二轮实现、交互边界与验收方式；不是学习效果报告。范围：升级 Dijkstra、0/1 背包、最大流，新增 VC→审稿委员会构造样板；保留当前 130 项课程、260 条输入推演。桌面验收宽度 1280 / 1440；本轮不设计手机界面。

## 1. 一套探索方式，保留数学动作

共享的是「选对象 → 看影响 → 执行 → 回退/分支对照 → 改输入验证」；不是把所有算法改成四个动词，也不要求每一步填写证明。用户决定候选、依赖、路径、方案或反例；加减、求和、更新相关读数默认自动完成。公式与图中的数保持同源。每个样板只在关键分歧处设置一个预测或解释点，其他时候允许连续操作。

统一外壳承担对象选择、预览、历史、输入编辑、证据与成本；领域模型承担数学合法性、策略条件、终止与结论。采用可复用的高层目标与局部动作组织，降低每关交互设计成本；不把这种组织方式当成所有算法的数学本质，不向学生讲「熵减」等内部设计术语。

自由实验由 `ExperimentScene` 承担，四个领域适配器 `simulation/experiment-*.ts` 通过 `sim.ts` 提供纯操作、报告与画面。`experiment-session.ts` 保存命令、游标和对照分支。原 `LabScene` / `simulation/interactive.ts` 保留有指定策略的演示、操练和挑战，任务与自由探索不同；两者互有入口，不以兼容层转换动作。旧版将无变化都算错的判定已改为按反馈性质判断；挑战暴露采用独立的单调账本。Pixi 场景持有交互，React 不接管算法状态。

## 2. 桌面与统一反馈

主画布保留对象身份与空间位置；右栏显示所选对象、影响、执行按钮、反馈与按需依据；顶栏常驻前进/回退与固定 A/B 对照入口；底部历史区显示游标、输入差异、结论与真实成本。1280 宽优先压缩留白，不缩小文字。依据按需展开于图下宽面板，场景按实际文字与公式高度扩展页面，不覆盖图或操作按钮。

选中使用轮廓与对象名；预览变化使用虚线及「预计」标签，提交后改成实线。只高亮本次关系，保留其他上下文。反向残量、未决值、不可行值用不同线型/标签表示。颜色不单独承担语义：红色仅表示不可执行或约束违反；偏离策略用琥珀色「可执行，未循策略」；有效反例用紫色「找到不一致」；通过局部校验用绿色「此项通过」，不提前宣布最优。

反馈按以下顺序呈现；不适用项可省略，不压成一个对/错灯：

| 维度 | 文案模板 | 证据 |
| --- | --- | --- |
| 可行性 | 可执行 / 不可执行：容量超出 2 | 对应边、容量或对象约束 |
| 策略 | 符合当前策略 / 可执行，未选最小暂距 | 当前候选与比较依据；非强制证明 |
| 结论 | 尚不能判定最优 / 本实例已获最优证书 / 找到构造不一致 | 未决量、割、依赖或反例见证 |
| 成本 | 本分支：松弛 5 次；本次 +1 | 真实执行的领域操作，区分人工选择与自动计算 |

只记录发生的操作，不能把用户点击次数写成时间复杂度。预览、无效提交、回退不重复增加当前分支算法成本；会话尝试数另计，回退不抹去。自动计算的工作量单列，禁止显示成用户独立完成。

## 3. 模式、预览与时间

- **演示**：保留一条可回放合法路线，标记「观看」；不能生成独立成绩。
- **探索**：可改输入、执行合法但偏离策略的动作、保留分支；反馈可完整展示结果与依据。探索完成只记探索记录。
- **练习**：有指定策略，可请求提示。指定策略不符时给出反馈并标记辅助；可通过顶栏进入自由实验，重新选择该问题的探索输入。不会把旧策略日志机械地迁入不同语义的自由分支。
- **挑战**：输入族与探索/练习隔离。提交前只展示所选对象、已知读数、涉及哪些对象及操作公式，不显示正确候选、未来数值、是否最优或策略判定。不能通过候选排序、禁用按钮、颜色或预览差值泄露答案。格式/类型约束可以预检；本题待判断的数学约束在提交后检验。

探索/练习的预览可显示所选动作的局部算术结果，不能自动推荐全局最优动作。挑战揭示针对本题的错误依据、具体提示或参考结果时，永久标记本次尝试为辅助；普通对象选择与读取已有状态不算辅助。撤销、重开、切换模式、刷新都不能洗掉同一挑战实例的提示暴露；同实例重做标为重做，独立成绩须来自未暴露的新实例。保留旧的独立记录但注明旧版判定口径，不能追溯升级为本轮独立。

时间操作采用「命令日志 + 游标」，回退后允许前进。执行新动作或改输入时保留原未来，创建新分支；本轮只需当前分支及一个固定对照分支，不做无限树编辑器。改输入保留旧分支，在新分支从初态重新计算，不把旧暂距/表格/流混入新问题。

A/B 对照先显示输入差异、当前读数、结论等级与实际成本。相同输入的不同策略可比较成本；不同输入明确标注「输入不同」，不得据此声称策略更快。未完成分支不显示参考最优答案。挑战不能对照已揭示答案的同实例分支继续获得独立成绩。

## 4. 四个样板的可验收分镜

### Dijkstra：决定哪个暂距可以定案

1. 起点出边松弛后，图上同时保留候选暂距和前驱线。用户选择一个候选，预览圈出它及待检查出边；探索模式可看局部变化，挑战不标最小者。
2. 用户确定候选，自动完成指定出边的算术；仍允许逐边选择检查顺序。出现同暂距时，两者均合法。已处理边及本次实际松弛次数可见。
3. 探索选择非最小候选可执行为「提前标记」；保留该错误策略的可观察后果。不得赋予 Dijkstra 定案证书，之后即使数值碰巧正确也不能恢复“全程遵循策略”。回退到分歧前另开 A/B 分支可恢复合法路线。
4. 改一条权重，保留旧解，重新求解并比较真实路径；默认仍限制非负权。负权扩展不在本轮实现范围。

预测错误：把「离起点的边最小」当「当前总暂距最小」、认为首次发现就定案、相等候选只能选一个。关键视觉证据：`d[u]+w(u,v)` 三个来源就地对应；前驱更换用实线迁移；提前标记后来被更短候选挑战时，同时展示旧值与具体路径见证。自由度边界：不允许不存在边或无来源的暂距；若自由分支选择冻结已标记点，要明确显示被忽略的更优候选，不能静默修正后声称原策略正确。

验收：同暂距两条路线都完成；非最小候选自由分支可保存且不授予定案证明；减小一条边权后新分支从初态开始，旧分支仍可读。

### 0/1 背包：连接依赖，再比较方案

1. 用户选择一个待研究格 `(i,c)`，图上显示物品重量/价值与容量刻度；不再只允许每行总容量格。系统可自动展开所需前置子问题，未计算值显示 `?`。
2. 用户连接「不取」和「取」的上一行依赖，系统完成加法；选择哪个候选写入当前格。探索允许保留可行但较差方案，标「可行，未满足此格最大值」，不能把它冒充正确 DP 表。
3. 回溯时同步亮起具体物品与容量变化；允许等值的取/不取。物品集合总重量/价值由实际选择计算，不能用参考最优数替代。
4. 在容量或一个物品参数的有界编辑后，另开分支，比较集合怎样变化；本轮不新增任意规模表格编辑器。

预测错误：从本行取依赖而重复使用同一物品、容量不足仍选取、认为局部价值最高必然最优。关键视觉证据：两个依赖箭头连到实际格；`c-w_i` 在容量刻度上落点；回溯中已经使用的物品保留身份。自由度边界：0/1 约束不允许同件重复；未决依赖可由系统补算但记录自动计算格数。错误依赖可以作为草稿连线检验，不能写入权威 DP 表。

验收：至少两个非末列格可选择并展示真实依赖；等值多解都接受；错误的同层依赖显示具体重复物品风险；非最优可行集合不会获得最优标签。

### 最大流：选择路线，也能撤回旧安排

1. 同时显示原边 `f/c` 和可按需展开的正反残量；用户逐边连接增广路径，可退一段或清空草稿。
2. 选完整路径后，系统可计算瓶颈（挑战若考瓶颈则提交后揭示）；用户决定增广量。探索接受 `0<Δ≤瓶颈` 的整数增广，较小量标「可行，未用满瓶颈」；策略练习可要求用满。
3. 走反向残量边时，原边流量实际减少，用反向箭头与 `−Δ` 显示，再更新路径其他边及总流。
4. 无增广路后用户检查可达集合与割；只有流可行且实际割容量等于流量，才显示本实例最优证书。换路径分支比较增广次数，不把任选合法路径称为 Edmonds–Karp。

预测错误：把反向残量当原图新增容量、认为当前路径堵住即全局结束、超过瓶颈仍能增广。关键视觉证据：同一原边的 `f` 与两向残量同步更新，割边明确从 S 指向 T，割容量逐边求和。自由度边界：简单 s-t 正残量路径、整数增广；不允许负流或超容量。保留任意合法路径，不强迫 BFS。

验收：存在真实反向边路线；较小合法增广能执行；超瓶颈提交无状态副作用；局部路径死路不会宣布最大流。

### VC→审稿委员会：构造映射，再找破坏它的见证

1. 左侧图 `G=(V,E),k`，右侧教授/议题列表。顶点与教授的一对一对象预先建立；用户按边创建议题并连接两名端点教授，检验预算 k 是否原样保留。系统承担编号、计数与连线布局。
2. 点击一条边，右侧对应议题及名单同亮；提交构造时逐项检查「每顶点有对应教授、每边有对应议题、名单恰为两个端点、预算不变」。遗漏/多连允许作为可修改草稿，不自动修成答案。
3. 用户选一个顶点集合，同步映射为委员集合；两侧分别显示人数、未覆盖边、无人审稿议题。允许超预算或不覆盖集合用于检验，标「见证不满足条件」，不是禁止选择。
4. 探索改坏一个名单后检验集合，若同一个集合在两侧表现不同，紫色显示映射见证；另独立枚举两侧是否各自存在合格集合，区分「集合映射失真」和「整个实例的 YES/NO 不同」。修订后可重试同一见证。本轮归约为自由构造样板，不提供独立挑战成绩。

固定小实例可枚举所有子集作校验，但面板明确「此实例共检查 2^|V| 个集合」。通过不等于一般归约证明。完成页另列一般论证：构造规模 O(|V|+|E|)；覆盖⇒合格委员会、合格委员会⇒覆盖；给定委员会可多项式核验；结合已知 VC 的 NP 完全性。学习者按需查看，不能用看完或枚举通过冒充其独立证明。

预测错误：归约方向反过来、给每条边只选一个任意端点、漏议题、改预算、用一个成功见证宣布等价。关键视觉证据：稳定的一对一对象映射、每条边两端到名单的两条线、反例中那一条未覆盖边/失真议题。自由度边界：本轮固定小图、编辑名单和集合，不做任意图语言或全 NP 归约编辑器。

验收：正确构造双向对应；删去一个端点映射后至少存在可展示的不一致见证；修订再测有效；NO 实例没有虚构成功委员会；实例枚举与一般证明分开展示。

## 5. 存档、迁移与交付门槛

自由实验另存 `algorithmia-experiments-v1`：四类各自记录规范输入、命令、游标、一个对照分支、累计尝试及本地事件。刷新由纯操作重放；回退保留未来，分歧执行自动留作对照。固定 A 时分配独立身份，交换不混合输入；损坏记录先备份原始值，无法备份则不覆盖。输入只在有界数字表单应用时生效。

原 `algorithmia-labs-v1` 保持可查看、可继续，不将旧动作猜测转换为自由探索命令，也不授予新的独立成绩。旧独立记录明确标为旧版判定；新 `independentV2` / `independentMetricsV2` 单列。`algorithmia-lab-exposure-v2` 按真实实例保留暴露与完成状态；重开、撤销、切换模式或刷新不清除。自由输入若恰与挑战实例相同，首次选择显示预览时也记录暴露。

`algorithmia-save-v1` 和 `algorithmia-course-v1` 不改写。130 课件推演、来源与预测检查点保持；新增操练入口不能将既有推演进度算为实验掌握。本文不是全面重写 130 个场景的授权。

交付至少附：四样板操作与规则测试；A/B 回退/重放/改输入/刷新恢复；旧三类存档保持及新版独立指标隔离；挑战预览泄题与辅助标记检查；1280/1440 的真实指针、键盘、减少运动截图；文字/遮罩/公式完整性；130×2 原课程路径回归。截图须能看到真实算法关系，不能仅以无文字相交代替视觉验收。实现缺项必须列明，不能凭本文宣称完成。

真人实验目前未开展。实验就绪标准：已记录本地动作、分支、尝试与接受状态，不上报网络；尚未建立真人实验的同意流程、预测/解释测量和统一任务脚本。后续可让学习者先预测，再操作、解释证据、换输入迁移；比较首次预测、公式来源定位、迁移解释与完成耗时，不只看通关率。未经实际招募、执行和分析，不报告学习收益。

设计启发是看见状态与变化、通过反馈构造理解，以及先具体体验再抽象；它们不是本站效果证据：[Bret Victor](https://worrydream.com/LearnableProgramming/)、[Red Blob Games](https://www.redblobgames.com/pathfinding/a-star/introduction.html)、[Nicky Case](https://ncase.me/)。已有《动画绘制方法论》里的旧 React lesson / DesignNotes 代码契约不重新引入；遵循当前 AGENTS 的 Pixi 与纯模拟边界。

## 6. 实现入口与验证

入口位于星域总览、课程航线、课堂主线与相关任务中的「自由实验室」。四样板共享选择、预计/当前切换、执行、回退、前进、输入编辑、A/B 和证据面板；每个领域保留自己的动作。每分支最多 1000 条命令、最多保留 2000 条本地事件；A/B 是当前与一个对照，不是无限分支树。

预览图与公式来自同一次纯推演，实际成本保持提交前值，预计增加量另列。背包错误手填值的下游不会冒充 OPT：未获独立校验的值带 `?`，自动补算工作量单列。最大流撤流后保留反向箭头、实际 `−Δ` 与残量；最优校验显示真实 S/T 与跨割边。Dijkstra 的数值校验与全过程策略证书分开；归约的小实例枚举与一般论证分开。

命令见 README 的第二轮浏览器流程；测试计划包含 11 个场景、152 次提交（其中 2 次无效）、152 次预览和 11 次刷新恢复，另以真实鼠标检查依赖、残量、教授映射与分支。最终执行结果见交付记录；本协议不会把预期数量当成已执行结果。

最终执行数字与修正遮罩审计后的结论见 [ROUND2-VERIFICATION.md](ROUND2-VERIFICATION.md)。A 只有一份；再次固定、分歧执行或换输入会替换它，界面明确说明该规则。
