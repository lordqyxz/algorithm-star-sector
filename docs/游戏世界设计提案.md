# 算法王国（Algorithmia）· 游戏世界式算法学习软件 · 设计提案 v1

> 定位一句话：一个 2D 可探索的游戏世界，玩家亲身"执行"算法、用步数与比较次数换奖牌、
> 在 Boss 战里对抗最坏情况输入——把 CLRS 的概念变成可玩、可输赢、可重玩的世界。

---

## 1. 为什么是"游戏世界"，而不是"更好的课件"

现有课件站的模型是"观看 + 步进"：学习者看算法演示。调研（Human Resource Machine、
Zachtronics 系列、LightBot、while True: learn()）反复证明更强的模型是"具身化执行"：

- 学习者**就是**执行者：亲手搬运"值"、扮演指针与主元，操作即理解；
- **成本即分数**：步数/比较次数/额外空间是三枚正交奖章，复杂度从"背结论"变成"冲金村"；
- **失败零惩罚**：错只是箱子放错位，改了重跑——试错循环是学习引擎；
- 关卡梯度"引入 → 变体 → 组合 → Boss"天然对应教学设计（单概念 → 输入变体 → 概念组合 → 最坏情况）。

## 2. 调研结论：抄什么，不抄什么

### 2.1 从游戏引擎工程抄（必需级）

| 模式 | 在本产品中的落地 |
| --- | --- |
| Command 模式 + 回放 | 玩家每个动作物化为命令对象；只存命令日志即可完整重放任意一关（GGPO/lockstep 原理；算法模拟天然确定性） |
| 确定性模拟 | `simulate(state, command) → {state, events}` 纯函数；种子化随机；浮点不参与排序类判定 |
| 关卡即数据资产 | 关卡、对话、奖章阈值、数据变体全部是 JSON；引擎是解释器，内容与代码分离 |
| 动画=状态的渲染 | 渲染器是模拟状态的纯函数；补间只负责"上一状态 → 下一状态"的对象恒常移动，绝不拥有游戏状态 |
| Game Loop（回合制版） | 算法世界天然是回合制：玩家命令或自动播放计时器驱动 tick；时间缩放=播放速度 |

### 2.2 明确不抄（过度设计）

- 完整 ECS 调度器/自动并行（Bevy/DOTS）：实体量 <10³，React 状态足够；
- 物理/碰撞管线、Double Buffer、对象池：2D 瓦片世界用不上；
- 自建可视化关卡编辑器：先用手写 JSON + 类型校验（M3 之后再议）；
- Godot/Unity Web 导出：包体 30–50MB，与 Web 交付冲突。

### 2.3 从教学游戏抄（机制清单）

| 机制 | 来源 | 教学对应 |
| --- | --- | --- |
| 数据具身化：角色搬运"值" | HRM | 变量、交换、插入可观察 |
| 步数/指令数=分数+双奖章 | HRM、Zachtronics | 时间/空间复杂度计分 |
| 正交多指标（cycles/bandwidth/activity） | EXAPUNKS | 最优性不唯一，帕累托权衡 |
| 指令槽稀缺 | Robozzle/LightBot | 循环与递归消除重复 |
| 方案封装为模块 | while True: learn() | 函数抽象、算法库 |
| 无限重试、失败=错误输出 | 全系列 | 低惩罚试错 |
| 引入→变体→组合→Boss | LightBot/Zachtronics | 教学梯度 |
| RTFM 手册/图鉴 | SHENZHEN I/O | 查阅习惯、深读材料 |

## 3. 游戏世界设计

### 3.1 世界地图（与 CLRS 章节对应）

```
                    [递归森林]                    [堆雪山]
                 递归塔·分治神殿                优先队列矿场
                      \                            /
 [排序平原] ———— [中央广场·算法学院] ———— [图论群岛*]
  插入驿站 · 归并城堡 · 快速比武场 · 计数蜂巢      BFS渡口·DFS迷林(*远期)
                      |
                  [哈希集市*] [动态规划工坊*]
```

- 每个区域 = 一章；每个区域 6–10 关，按"引入 → 变体 → 组合 → Boss"排列；
- 区域之间用传送门连接，门上是"预测门"：答对下一状态才能通过（复用预测题机制，变成世界内交互）。

### 3.2 五种玩法循环

1. **操演关（Execute）**——玩家亲自动手：角色走到货架前，拿起 key、逐格右移、放回空位；
   目标：把整排货架排好。教学的是算法的"机械动作"。
2. **指挥关（Command）**——玩家拖动指令卡（比较/交换/前进/循环…）编成程序，让小精灵自动执行；
   指令槽有限 → 逼出循环与递归（Robozzle 机制）。教学的是"算法=程序"。
3. **预测门（Gate）**——世界内掩体门：展示当前状态，必须预测下一次变化才能通行。
4. **Boss 战**——对手发送针对性输入（如已排序数组逼出快排最坏情况）；
   Boss 血条=剩余递归深度；玩家从道具栏选"随机主元卡"反制。教学的是复杂度条件的威力。
5. **图鉴（Codex）**——世界各处的"魔法书"，翻开即进入对应算法的完整课件（现有 trace 引擎课程
   作为世界内的教学插页复用；世界负责动机，图鉴负责深度）。

### 3.3 评分 = 复杂度内化（本产品的灵魂）

每关三枚正交奖章（EXAPUNKS 式）：

- ⚡ **步数**：角色动作次数 → 直觉感受"时间复杂度"；
- 🔍 **比较**：比较操作次数 → 感受"比较次数下界"；
- 💾 **空间**：动用的额外暂存格 → 感受"空间复杂度"。

金/银/铜阈值由算法的理论界给出（例：插入排序 n=6 时 ⚡≤7 金）。同一关的三种数据变体
（有序/乱序/逆序）复用同一套阈值——玩家在逆序关怎么都拿不到金的时刻，就是 Θ(n²) 被身体
理解的时刻。世界内所有输入数据都是"关卡变体"数据，切换变体=重新生成关卡实例。

### 3.4 进度与激励

- 徽章图鉴（概念收集品：循环不变量徽章、稳定排序徽章…）；
- 区域完成度、成就墙；**不做**每日打卡/排行榜（教学场景优先，避免 Duolingo 式机制错配）。

## 4. 软件架构（全新设计，五层）

```
┌──────────────────────────────────────────────┐
│ 世界层 World      地图/角色移动/传送门/NPC/对话 │  React + SVG/DOM
├──────────────────────────────────────────────┤
│ 渲染层 Present    状态→像素 的纯函数 + FLIP 补间 │  状态快照 diff
├──────────────────────────────────────────────┤
│ 模拟层 Simulate   simulate(state, cmd) 纯函数  │  命令日志=存档=回放
├──────────────────────────────────────────────┤
│ 内容层 Content    关卡 JSON / 对话脚本 / 图鉴   │  数据资产 + 类型校验
├──────────────────────────────────────────────┤
│ 存档层 Save       命令日志 + 徽章 + 进度        │  localStorage
└──────────────────────────────────────────────┘
```

- **模拟层是唯一权威**（游戏规则）；世界层是"壳"；渲染层无状态；
  这同时就是"数据和算法分开"的延伸：关卡与玩法规则都是数据，引擎只是解释器。
- **命令日志即存档即回放**：localStorage 只存命令序列 + 种子，任何一关可精确重放/回看
  （格斗游戏 rollback 原理在回合制上的退化版，成本极低）。
- **动画原则**：对象身份（value#seed 令牌）跨状态保持，补间移动真实对象；可随时暂停/回退；
  reduced-motion 直接显示终态。

### 4.1 关卡数据格式（示意）


### 4.2 模拟层接口（示意）

```ts
type Command = { type: 'moveRight' } | { type: 'pick' } | { type: 'drop' } | { type: 'compare' } | …
type Event   = { t: 'moved' } | { t: 'picked'; cell: string } | { t: 'compared'; verdict: … } | …
function simulate(state: LevelState, command: Command): { state: LevelState; events: Event[] }
```

关卡类型（execute/command/boss）各实现一个 `simulate`；世界层、渲染层、存档层对具体算法无感知。

## 5. 技术选型（LLM 视角）

| 维度 | 决定 |
| --- | --- |
| 渲染 | **纯 SVG/DOM + React**（首选）：语料最富、可达性/公式混排免费、状态即真相；实体规模小 |
| 需要更强表现时 | 叠加 **PixiJS** 渲染层（语料多）；**不用** Phaser（无物理/相机需求时是过度设计）、不用 Godot Web 导出（包体不可接受） |
| 语言/构建 | 沿用 TypeScript + Vite；与课件站同一 monorepo 或子路由共存 |
| 状态 | 模拟层纯函数 + React 外部 store（如 zustand 或 useReducer）；不引重框架 |
| 测试 | 模拟层纯函数单测：每关金/银阈值可被自动验证（LLM 生成关卡后可程序化校验） |

## 6. 里程碑

- **M0 · 可玩原型（先做）**：排序平原第一村——插入排序操演关 ×3 变体 + 世界地图骨架（单区域）
  + 命令/模拟/渲染三层 + 三奖章计分 + localStorage 存档。验收：亲手玩通 3 关、重放无偏差。
- **M1**：指令卡指挥关（Robozzle 式）+ 预测门 + 归并城堡（分治：双工人合并）。
- **M2**：快速比武场 Boss 战（随机主元道具）+ 堆雪山优先队列矿场 + 世界图鉴接入现有课件。
- **M3**：关卡编辑器（JSON 表单）、更多区域（图论群岛、DP 工坊）。

## 7. 与现有课件站的关系

- 课件站继续存在，并作为游戏世界的"图鉴"内容源（trace 引擎课程直接嵌入图鉴弹窗）；
- 现有 trace 数据格式与"数据/算法分离"哲学被继承到关卡 JSON 与模拟层；
- 入口改造：站点首页提供「课件模式 / 王国模式」双入口。

## 8. 风险与坑（调研 D 部分消化）

1. **动画先于教学**（最常见死法）：一切动画必须可暂停/可回退/对象恒常——已在架构层禁止；
2. **概念无操作化**：每个概念必须落为机制（复杂度=奖章、不变量=绿色货架区、最优性=正交奖牌），
   不做"贴图术语"；
3. **难度悬崖**：每关必须从上一关的可复用动作开始；失败只损失一次重跑；
4. **内容成本**：关卡是 JSON 数据 + 阈值自动校验，可由 LLM 批量产出、程序验证，控制人工成本。
